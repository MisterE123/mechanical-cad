## Scope and current boundaries

The approved [design](architecture/arc_authoring/PROPOSAL.md) is a four-gate
build/edit/save preview. Gate A was independently qualified and committed as
`bef37be9076577f96a9c05708104730942b787c0`: explicit journal3/UI2/envelope3,
arc commands and strict dormant operation contracts. Its 1,498 focused pure
cases and 36 native sidecar/host-owner controls are distinct from Blender UI
qualification and from the earlier full data-service regression.

Gate B adopts explicit schema-derived result3 in the shared General and Part
owners. The whole exact candidate selects the contract, including arc-empty
schema3; an upgraded authoring envelope by itself still selects legacy result2.
Every initial/trial/downstream/Finish handoff retains an independent expected
PreparedRequest and compares full G, including nonce. Same-owner clones transfer
the original complete evidence/prepared chain. Claims remain once-only; current
reads revalidate and observed generation changes cannot be undone by rollback.

Part publication uses the existing single reversible canonical/display/layout
transaction. General driver acceptance verifies the complete chain inside its
reversible saved-slot transaction, preserving externally replaced slot bytes.
A successful trial followed by a failed native build keeps exact pending text
and a runtime-only scalar attempt report. That report supplies no solved seeds,
accepted driver, Finish or Part authority.

Schema3 Check Geometry, STEP/STL, guarded snapshots and Assembly sources remain
unsupported. Core entry points reject before leases, native work, accepted-state
invalidation, or file/source writes. UI operator wrappers may update only their
existing `last_action_error` diagnostic, alongside operator reporting; they must
preserve authored data, pending raw input, accepted authority, display and reports.
Rectangle and every downstream result consumer explicitly remain result2.
An existing valid result2 Assembly remains usable when the working Part contains
arcs; capture/update from that schema3 working Part is unavailable.

The pure dispatcher now routes envelope3 explicitly. Old codecs remain strict
and the frozen 39-case legacy byte corpus remains exact. Phase-aware exact point
references use the same detached proposal/CAS seam; they do not project, snap,
allocate early, restore capture or create implicit constraints. Layout1 keeps
its existing fields and acquires no geometry authority.

## Next usable workflow and retained limitation

Gate C adds the actual Center/Start/End gesture, phase-aware existing-point picker,
reverse sweep, finite-arc display/picking and radius targeting only after this
owner review passes. Gate D requires the final full regression and exact installed
manual build/edit/save and two-process reopen workflow.

The first supported arc profile is one arc and two shared-ID radial lines, with
its optional sole extrusion. Radius and height support are 1–1000 mm in the
qualified exact frame/placement domain. The authoring editor is XY. Unsupported
open arc profiles remain editable/suspendable drafts, not canonical Finish output.

The retained underconstrained DoF5 periodic native-range failure remains a real
conservative limitation. A genuine successful solve can still be followed by a
native profile rejection. Recovery must retain authored points, direction, IDs,
raw input and original committed Part, show the separate outcomes, and require
an explicit edit/Check/Undo action. No hidden reseeding, modulo fallback,
automatic retry or tolerance widening is introduced.
