# Bounded sector-output owner implementation

The current source implements the coordinated Gate C Part owner/UI slice, based
on clean `de70a45c2d34e74d61adb93e7f7db881bd6f8404`. This is an implementation
candidate, not an installed-package result or release. Pure owner/publication
verification is in progress; native registered-operator, two-process persistence,
exact offline ZIP and manual-GUI qualification remain separate gates.

## Finite source boundary

Only one schema-3 directed arc with two shared-ID radial lines and one active
direct extrusion is eligible for Geometry Check, STEP and STL: exact zero origin,
identity quaternion and the existing 1–1000 mm solved radius/height domain. Each
action requests explicit result 3, solves and replays the exact committed source,
and validates a fresh complete guarded completion. Nonzero degrees of freedom
alone do not disqualify a valid solid. Authored seeds and IDs remain unchanged.

Profile-only or selected-profile output, arc-empty schema 3, extra branches or
consumers, broader curves and arbitrary planes remain rejected before lease
acquisition or state changes. Snapshot/Assembly and Rectangle owners retain their
existing boundaries. Ordinary result-2 Parts keep their original contracts.

The two geometry capability markers and backend observer are activated together
with the exact Part selector, owner-bound result version, UI availability and help.
Observed implementation origins, function identity links and every solver/arc/replay
companion remain mandatory. A marker alone never establishes capability or CAD
evidence. The one historical projection callsite uses the independently prepared
operation and captured version; saved reports cannot recreate runtime authority.

A valid replay can accompany failed checking or file output. UNKNOWN means that
an export may have happened without a validated completion; OUTDATED retains a
validated earlier file write when current CAD publication is rejected. Neither
outcome automatically retries. Maximum-sector Check/STEP success does not imply
STL success: the unchanged float32 precision gate can reject STL while preserving
the prior destination. File replacement is outside Blender Undo.

before this owner slice began. Their results qualify their exact earlier source;
they do not establish native owner, persistence, installed or GUI behavior for
this new candidate. Fresh native-blocked focused tests must cover selection,
capability observations, exact evidence, once-only publication and failure seams.

unpublished completion. Frozen historical file metadata survives partial report
failures; unavailable scene storage instead raises a diagnostic retaining the
original confirmed export evidence. No new authority or broad rollback path is
introduced, and result-2 exception behavior remains unchanged. Native verification
of these corrected seams is still required.

The finite source/harness historical inverse pair is re-anchored to de70a45 and
must preserve its test-only inventory repair before applying the unchanged older
redundancy/standalone/Windows/authoring chains. Every existing fixture, legacy

Constructor, solver, replay engine, model, native dependency/runtime and public
Windows admission remain unchanged. No core kernel is imported into Blender.
The existing bundled setup and retained cleanup-quarantine behavior remain intact.
Real-host Windows testing stays deferred.
