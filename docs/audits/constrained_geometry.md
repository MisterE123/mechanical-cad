# Independent constrained-sketch audit

Audit date: 2026-10-16. This is a bounded numerical and persistence audit of the
Linux sidecar, not a GUI usability test or a manufacturing certification.

## Reproduce

Install the project with its sketch and development dependencies in the sidecar
environment, then run from the repository root:

```sh
.venv/bin/python scripts/audit_constrained_geometry.py \
  --output /tmp/constrained_geometry_audit.json
```

Success requires exit code zero and `CONSTRAINED_GEOMETRY_AUDIT_PASSED`. The JSON
evidence records native package/Python versions and section results. A failed
section exits nonzero and records the failure if `--output` was supplied; do not
interpret completed earlier sections as a complete pass. OCCT may print export
messages to stdout, so use the evidence file rather than parsing stdout as JSON.

The script uses fixed seeds and fixed case limits. It runs only when invoked;
ordinary pytest does not collect it. STEP/STL files are written into an isolated
temporary directory and removed automatically. The audit does not edit models,
change saved seeds, operate Blender, or modify repository files. `--output`
writes only the explicitly selected evidence file.

Focused sections can be selected or combined:

```sh
.venv/bin/python scripts/audit_constrained_geometry.py \
  --section duplicates --section quaternions
```

### Legacy serializer oracle

The expected aggregate was computed independently using
`src/mechanical_cad/model.py` from commit `e987f14`, before typed sketches were
added. For the 500 dictionaries generated by `schema_cases()`, collect the legacy
`Document.from_dict(case).content_hash` values in order, join them with newlines,
append one trailing newline, then SHA-256 the UTF-8 bytes. The expected digest is:

```text
0f685a275c2b87473f9d31572896fb3a0b8c57b12eba20e417c0313364655b15
```

The audit therefore does not need Git history or execute historical source at
runtime. The aggregate detects any change in the exact legacy canonical JSON
bytes, including numeric representation, defaults, key ordering and formatting.

## Findings and resolution

1. **Redundant equations from unsolved seeds:** duplicating `axis0` in the shipped
   example originally caused native `INCONSISTENT`, naming `anchor` as a diagnostic
   candidate despite the mathematical system being feasible. Exact duplicate
   equations are now skipped only during native compilation; all saved IDs and
   expressions remain intact and redundancy is explicitly reported.
2. **Symmetric-reference seed continuity:** the first mitigation could choose an
   earlier-ID duplicate with reversed coincidence endpoints and move an
   underconstrained profile by 0.4 mm. Canonical temporary endpoint direction and
   equation ordering now make native input independent of duplicate IDs and
   symmetric-reference direction. The 84-case section guards this correction.
3. **Long, rotated, near-unit workplanes:** the solver succeeded with zero local
   residual, but implicit OCCT wire-plane fitting rejected a 1,000,000 × 30 mm
   profile after an accepted 5e-10 norm-squared perturbation. Constructing the
   already-known explicit workplane avoids that unnecessary fit. The 24-case
   section guards the full solver/profile/extrusion path, not merely the solver.
4. **Nanometre-scale boundary:** 1e-6 mm is an input guard, not a guarantee that
   every aspect ratio can be meshed. The original audit found conservative
   profile or tessellation failures at that limit. Dedicated integration tests
   preserve failed/blocked status rather than weakening geometry validation.

Failed-constraint IDs remain diagnostic candidates, not proof of a contradiction
or permission to delete a relation. The pinned native solver can still fail on
feasible, poorly conditioned systems; exact-duplicate handling is not general
algebraic redundancy elimination.

## Latest evidence

The complete checked-in audit passed all seven sections after the focused
corrections on 2026-10-16: CPython 3.12.14, slvs 3.2, and
cadquery-ocp-novtk 8.0.1.1.0. The 180 polygon, 500 schema, 84 duplicate, 24
quaternion, five rejection and 12 dual-format export cases passed. The triangle
sample contains 1,499 successful edit pairs with no mirror flips and one
pair (index 1306) that conservatively returns `DIDNT_CONVERGE` on both solves. That
pair retains its original geometry and exposes no valid DoF; it is not counted
as a successful branch-preservation case. The script fails if fewer than 1,499
pairs succeed or if any successful pair flips.

These checks complement the ordinary unit/integration and Blender suites. They
do not establish general branch preservation, arbitrary-loop support, solver
timeouts, performance at all resource limits, or compatibility on untested
platforms/native versions.
